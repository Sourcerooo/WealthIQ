# CLAUDE.md
Guidance for Claude Code and other agentic assistants working in `WealthIQ`.

## What this project is
WealthIQ is a **personal, single-user, local** wealth-management tool. v1 priority is a **German annual tax report** (Finanzamt-grade basis): import an IBKR XML statement → canonical ledger in SQLite → yearly tax report in a local Blazor dashboard with drill-down to the source.

**Explicitly out of v1 scope** (do not add unless asked): additional brokers beyond IBKR + Trader's Place, trading strategies/backtesting, multi-base-currency. (PDF export *was* out of scope; it shipped later as the printable tax report, see below.) The retired "Sigmatic" project was the reference implementation; its tax logic was ported, its trading engine was not. A read-only **portfolio dashboard** (current holdings, valuation, allocation) has since shipped as the first feature built on top of the v1 tax core.

### Web UI ("Midnight Ledger" design)
The dashboard uses a dark-first emerald-on-navy theme with a left navigation drawer and a dark/light toggle. Key pieces (all under `src/WealthIQ.Web`):
- Theme: central `MudTheme` in `Theme/WealthIqTheme.cs` (light + dark palettes), wired in `Components/Layout/MainLayout.razor` via `MudThemeProvider`.
- Theme persistence: `Services/ThemePreferenceService.cs` stores the dark/light choice in `localStorage` (JS interop, loaded in `OnAfterRenderAsync(firstRender)`).
- Shared presentational components in `Components/Shared/`: `PageHeader` (renders the page `<h1>` — keep it so `FocusOnNavigate Selector="h1"` works), `SectionCard`, `StatCard`.
- Styling/motion: `wwwroot/wealthiq.css` (`.wiq-*` classes, tabular numerals, entrance animations, honors `prefers-reduced-motion`) and `wwwroot/wealthiq.js` (`window.wealthiq` — theme localStorage helpers + count-up enhancement; the static text is already the final value, JS only animates).
- Navigation drawer groups pages as **Bericht** (Steuerreport), **Daten erfassen** (Import), **Daten ansehen** (Data Browser: Ledger = `/browse/ledger`, Kurschart = `/browse/prices`, Wechselkurse = `/browse/fx`), **Stammdaten** (Marktdaten = `/data-admin`, Instrumente), and a bottom-pinned **Diagnose** (Diagnose = `/diagnostics`, Audit-Trail).
- **Data Browser** (`Components/Pages/Browse/`) is read-only and queries `WealthIqDbContext`/`ILedgerStore` directly (same precedent as `DataAdmin`/`Audit`): `LedgerBrowser` (ledger split by entry kind, original currency), `PriceChart` (per-symbol adjusted candlestick), `FxChart` (per-currency `X/EUR` line). `LedgerBrowser` has a top **account dropdown** (lists only accounts with entries, preselects the first; switching re-filters the already-loaded entries in memory) and hosts the **ledger delete** (button + "Rohdateien löschen" checkbox via `ILedgerClearService`) — `DataAdmin` no longer does.
- **Portfolio dashboard** (`Components/Pages/Dashboard/Dashboard.razor`, route `/` — the landing page; Steuerreport moved to `/steuerreport`) shows current holdings grouped by ISIN with average buy price, EUR market value, and unrealized P&L, an asset-class allocation donut, YTD KPIs (Gesamtwert securities-only, unrealized G/V, Dividenden, Realisiert), a Yahoo price-refresh button (`HistoricalPriceRefreshService`), and a master–detail candlestick (`LightweightChart` with an optional `ReferencePrice` avg-buy line; instrument picker spans all priced instruments incl. non-held). Valuation logic lives in `Application/Valuation/PortfolioValuationService` (extended with cost basis / avg buy / unrealized P&L); ISIN rollup + "Alle" view + allocation + YTD dividends/realized live in `Application/Dashboard/PortfolioDashboardService`. Unlike the tax engine, the dashboard is **resilient**: a missing price/FX flags one position ("Kurs fehlt") and excludes it from totals instead of failing. Planned follow-up phases: **Pillar 2** (net worth over time, incl. cash) and **Pillar 3** (rebalancing / target positions).
- `PriceChart` preselects the first instrument and **remembers the selection across navigation** via the scoped `Services/ChartSelectionState` (per-circuit, resets on full reload); its `MudAutocomplete` is `Clearable="false"`.
- Charts: the Steuerreport donut still uses MudBlazor's built-in `MudChart` (one `ChartSeries<double>` whose `Data` holds per-category segment values, rounded to 2 decimals). The Data Browser candlestick/line charts use **TradingView Lightweight Charts v4** — vendored at `wwwroot/lib/lightweight-charts/`, interop in `wwwroot/wiq-charts.js` (global `window.wiqCharts`), wrapped by the reusable `Components/Shared/LightweightChart.razor` (`Kind="candlestick"|"line"`, `IAsyncDisposable`, dark/light theme sync, optional `InitialRangeDays` to open zoomed to the last N days — Kurschart uses `365`). Adjusted OHLC is derived by `AdjustedPriceCalculator.ToAdjusted` (factor `AdjustedClose/Close`, display only — the tax engine still uses raw `Close`).
- **Marktdaten** (`DataAdmin`) hosts Historische Kurse, Wechselkurse, Basiszins, and Dividenden-Aliases (Trader's Place) (no Ledger/Instrumente panels — Instrumente has its own nav entry). Wechselkurse supports **incremental refresh** (`FxRateRefreshService.RefreshIncrementalAsync`, tracked set = stored currencies ∪ USD/GBP/CHF) and **add-currency backfill** (`AddCurrencyAsync` over the static ECB currency list; `IFxRateProvider.FetchAsync` takes a currency filter). Basiszins is a single **ascending** editable year→rate table (`MudTable` `RowEditCommit` + per-row delete + inline add-row via `BasisInterestRateRefreshService.SetManualAsync`/`DeleteAsync`); the BMF auto-fetch button was removed from the UI. Dividenden-Aliases is an editable alias→ISIN table (`IDividendAliasMap`/`DbDividendAliasMap`/`DbDividendAliasStore`) used by the Trader's Place importer to resolve dividend cash entries to instruments; unmapped alias = blocking import Error.
- `GermanTaxEntry` carries display-only fields (`OpenedOn`/`Fees`/`Origin`, plus `SourceReference`/`CloseReference`/`SourceFile`/`OriginalAmount`/`OriginalCurrency` and the Vorabpauschale inputs `YearStartPrice`/`YearEndPrice`/`BasisRate`/`HeldQuantity`/`DistributionPerShare`/`MonthFactor`) populated by `GermanTaxCalculator` (additive, never affect tax math). It also carries `AccountId` and `WithheldKESt` (broker-withheld German capital-gains tax captured on `TradeEntry.WithheldTax`; excluded from FIFO gain math, surfaced in `TaxReportSummary.WithheldKESt` as a KPI), plus `AssetClass` (nullable `TaxAssetClass`) and `InstrumentName` — display/mapping-only, never tax math — from which `Application/Tax/Report/Forms/TaxFormReportBuilder.Build` builds the Anlage KAP/KAP-INV line report (line-number schema = Formularstand **VZ 2025**), rendered by `Components/Shared/TaxFormBlock.razor` on `/steuerreport` and in the PDF. The Steuerreport tables show these via **in-place expander rows** ("Quelle"/"Weniger") instead of navigating away; the Verkäufe summary "Anzeigen" scroll-and-highlights its detail row (`wealthiq.scrollAndHighlight`). The "Verrechn. Vorabpausch." column shows only on the Verkäufe summary (hidden for Dividenden/Zinsen/Vorabpauschale where it is always 0). The Steuerreport page has an **account dropdown** (`AnnualTaxReportService` returns `IReadOnlyList<AccountTaxReport>`; each account's results shown independently).
  - `TaxFormReportBuilder.Build(report, sourceSystem)` picks the route **by broker, not by withheld tax**: `Forms/DomesticPayingAgents.SourceSystems` lists the source systems that act as an *inländische Zahlstelle* (today `"TradersPlace"` only; `"IBKR"` is foreign), matched case-insensitively. Membership means the income is certified on a Steuerbescheinigung and declared on Anlage KAP Zeile 7 — it must **not** be re-entered on KAP-INV. An unknown/empty source system takes the foreign (KAP-INV) route, the safe default. Add a broker to that set only if it withholds German KESt itself. A **foreign** account with `WithheldKESt > 0` stays on KAP-INV but gets an "Achtung" note on the KAP section telling the user to check that account's Steuerbescheinigung (Zeile 37 keeps the amount). A Vorabpauschale on a non-fund class is a **blocking error** (KAP-INV Zeilen 9–13 cover funds only; it would otherwise vanish from the form while still counting toward the estimated tax).
  - Both pages build the form report **defensively** (`BuildForms()` returning `(Report, Error)`): the builder's fail-fast message renders as a `MudAlert` (Steuerreport) / `.wiq-p-notice` (print) in place of the form block, and the rest of the page still renders. An exception escaping the render tree would tear down the Blazor circuit and hide the very tables that identify the offending instrument.
  - **Naming trap:** two different things are called *asset class*. `Instrument.AssetClass` / `GermanTaxEntry.AssetClass` / `InstrumentAdminDto.AssetClass` are the **tax** classification (`TaxAssetClass?`, drives KAP vs. KAP-INV). `PortfolioPositionSnapshot.AssetClass` and the dashboard models hold a `string` copy of `Instrument.Type` (free text, e.g. `ETF_EQUITY`) used only for the allocation donut. Deliberately not renamed; check the type before reaching for "the asset class" on the dashboard.
- **Printable tax report / PDF export** (`Components/Pages/TaxReportPrint.razor`, route `/steuerreport/print?account=<nr>&year=<jahr>`), reached from the Steuerreport page's "PDF-Export" button. Renders one account-year as an **A4 landscape** document: the aggregation shaped like the Anlage KAP / KAP-INV lines, then five numbered Einzelnachweise (A Veräußerungen, B Dividenden, C Zinsen, D Vorabpauschalen, E Quellensteuer), each starting on a new page and cross-referenced from the summary. Pagination uses **Paged.js v0.4.3** (vendored at `wwwroot/lib/pagedjs/`, driven by `wwwroot/steuerreport-print.js`); the browser's print dialog produces the PDF. `wwwroot/steuerreport-print.css` is the *document* stylesheet handed to Paged.js (`@page` geometry, running header via `position: running()`, page numbers via `counter(page)` in the `@top-right` margin box — counters do **not** resolve inside a running element); screen-only chrome lives in `wwwroot/steuerreport-print-screen.css`. Layout `Components/Layout/PrintLayout.razor` (no MudBlazor chrome); header `Components/Shared/TaxReportPrintHeader.razor` (broker wordmark per `AccountTaxReport.SourceSystem`; the wordmarks are CSS placeholders, not licensed assets). Blazor renders into a hidden `#wiq-print-source` and Paged.js paginates a **clone** into `#wiq-print-target` so the two renderers never contend for the same DOM.
  - Report conventions worth preserving: Nachweis A sums **only** the taxable column for its grand total (a Roh-G/V grand total reads as an equation that does not hold — the Teilfreistellung quota differs per instrument and `RawAmount` already has the offset Vorabpauschale deducted); but Nachweise A/B/D also group entries by Fondsart with a `wiq-p-subtotal` row per group (ordered by `KapInvRows.All`), and there the `RawAmount` subtotal is sound and is exactly the figure the KAP-INV Ermittlung wants (B: Zeilen 4–8, D: Zeilen 30–45, A: Zeilen 46–56), because the Teilfreistellung quota is uniform within one fund class; the Vorabpauschale column is labelled "darin Vorabp."; the Monatsfaktor prints as `7 / 12`, not `0,58`; provenance lines cite the broker's original file name via `TaxReportPrintFormat.SourceFileName`, which strips the raw-file-store directory and the `wealthiq-upload-<guid>-` prefix that `Import.razor` adds.
  - Header identity data (name, address, tax id) binds from the **`TaxpayerProfile`** configuration section into `Options/TaxpayerProfileOptions`. `appsettings.json` carries empty placeholders; the real values belong in **`appsettings.Local.json`** (gitignored, registered as an optional source in `Program.cs`) so personal data stays out of version control.
- Note: `Components/Shared/` Razor components have no `Class`/`Style` parameter; apply outer spacing via a wrapper `div`. Icon-only `MudIconButton`s use `aria-label` (not `Title`, which trips the MUD0002 analyzer).

## Dependency direction (keep strict)
- `Application → Domain`
- `Infrastructure → Application, Domain`
- `Web → Application, Domain, Infrastructure` (composition only)
- `Tests → Application, Domain, Infrastructure`

Rules: never depend from `Domain` outward; business rules live in `Domain`/`Application`; broker/parsing/persistence concerns live in `Infrastructure`; **only `Web` references `Infrastructure`** so persistence does not leak into Application/Domain.

## Architecture principles (inviolable)
- **Canonical ledger is the source of truth.** Positions, realizations, and tax are reconstructed by **replay** from the ordered, immutable `PortfolioEntry` set — never the reverse.
- Ledger entries store amounts in **original currency**. Never embed an EUR conversion in an entry.
- **FX rule:** convert to EUR only at replay/accumulation, using the FX rate **at the event's own time** (trade/booking/acquisition date), not at accumulation time. A **missing required rate is a blocking error** — no silent fallback. (`CsvFxRateLookup` / `DbFxRateLookup` support `ExactDate` and `NextAvailableOnOrAfter` roll-forward for statutory dates.)
- **Re-import is idempotent** — dedup over `SourceProvenance` transaction reference.
- **Fail-fast everywhere.** Each source record becomes a canonical entry or a structured `ImportDiagnostic` (Severity Info/Warning/Error/Fatal). Collect *all* diagnostics, then abort the batch transactionally if any are blocking. No silent drops; missing reference/FX/price data fails loudly.
- `PortfolioLedger` ordering is deterministic: same `OccurredAt` ties break on `SourceProvenance.SourceRecordReference` (broker booking order = true FIFO). Do not reintroduce GUID-based tie-breaks.

## Data layout (`data/`)
- `data/reference/` — **committed** seed reference data (`basiszins.csv`, `instruments.json`, `fx_rates.csv`, `listings.json`, `historical_prices.csv`, `tradersplace_dividend_aliases.csv`). Seeded into SQLite on first run. `prices.csv` and `market_data_mappings.json` are **retired**; year-start/year-end prices are derived from `HistoricalPrice` bars (`ProviderSymbol, Date`). New tables: `HistoricalPrice`, `InstrumentListing` (`Isin, Currency`), `DataRefreshLog` (`Dataset`), `DividendAliases`. `InstrumentProfile` now carries `Type`, `SubjectToVorabpauschale`, and `TaxAssetClass` columns; `instruments.json` mirrors the latter two as `subject_to_vorabpauschale`/`tax_asset_class` (snake_case codes, translated by `TaxAssetClassCode`). `Type` is free text editable in the Instrumente admin UI, so it can drift from the seed file's vocabulary — the `TaxAssetClass` backfill migration keyed on `Type` and missed both gold ETCs because the live DB carried `ETF_METAL` where the seed said `ETC` (corrected by a follow-up migration, `TaxAssetClassMetalEtc`). The tax-form report relies on `TaxAssetClass`, not `Type`; an unclassified instrument fails loudly, naming the ISIN and pointing at Stammdaten → Instrumente. The `tax_asset_class` code is **validated on every write**, not only on read: `ReferenceDataSeeder` throws (committed file = repo defect), `DbInstrumentReferenceAdmin.UploadAsync` skips the row with a per-instrument warning like an invalid `tfs_quote`, and `SaveAsync` rejects an undefined enum value. Writes normalise through `TaxAssetClassCode.Parse`/`ToCode`, so stored codes are canonically spelled. (This supersedes the earlier decision to defer validation to read time — an unparseable stored code used to break the tax report *and* the Instrumente admin page, i.e. the one screen that could repair it.) Reference data is refreshable from the internet (Yahoo Finance / ECB / BMF) via the `/data-admin` page; committed files remain the offline bootstrap seed and CI fixtures. Python download scripts are **retired**; native C# providers replace them.
- `data/test/` — **committed** golden test fixtures: `statements/*.xml` (IBKR samples 2021–2025) + `configuration/` (csv/json the regression test reads) + `tradersplace/` (Trader's Place CSV exports + configuration feeding `TradersPlaceRegressionTests`). **Must not be gitignored** — the end-to-end regression tests read them, so gitignoring them breaks CI.
- `data/app/` — local runtime DB/raw files. **Gitignored.**
- `data/design_template/` — local-only design notes. **Gitignored.**

## Tax-pipeline guardrails
- Lot matching is **FIFO**; distinguish open lots from realized entries; partial closes preserve remaining quantity + pro-rata cost allocation; over-closes open an opposite-direction lot (short), never silently dropped.
- **Vorabpauschale** (§18 InvStG) — only for instruments where `SubjectToVorabpauschale = true` (explicit profile required; no inference). Per year Y with `Basiszins(Y) > 0`, for each held long lot: `basisErtrag = yearStartRedemptionPrice × Basiszins × 0.7`; `cap = max(0, (yearEnd − yearStart) + distributionsPerShare)`; `vorabFull = max(0, min(basisErtrag, cap) − distributionsPerShare)`; `vorabPerShare = vorabFull × monthFactor` where `monthFactor = (13 − openMonth)/12` in the acquisition year, else 1. Posted to year+1 (Jan 1); previously-taxed Vorabpauschale deducted at sale. `Basiszins = null` for a held year → blocking error. `Basiszins ≤ 0` → skip year (no price lookup).
- **Teilfreistellung** (e.g. 30% for equity funds) applies to sales, dividends, and Vorabpauschale; driven by the instrument profile. No defaults — a held instrument with no profile is a blocking error.
- Importer accepts only `STK`/`FUND`; forex/cash/other asset classes → Info diagnostic + skip. Cancellation pairs ("(Ca.)") are matched and removed.
- **Import pipeline** selects an importer via `IStatementImporter.CanImport` from `IEnumerable<IStatementImporter>` (first match wins). Multi-file brokers ingest a directory via `IRawFileStore.IngestDirectory`. Currently registered importers: `IbkrStatementImporter`, `TradersPlaceStatementImporter`.
- **Trader's Place importer** (`TradersPlaceStatementImporter`, `Infrastructure/TradersPlace/Import/`) ingests TWO CSV exports in one batch: *Depotumsätze* (trades: qty/price/fees/KeSt) + *Kontoumsätze* (cash: dividends resolved via alias map, positive Kontoabschluss → interest). Header-routing + per-type routing avoids double-counting trade rows that appear in both files. Files are Windows-1252/Latin-1 with broker-corrupted umlauts (U+FFFD replaced); footer/transfer detection is ASCII-safe.
- Golden baseline: `tests/.../Application/Tax/GermanTaxRegressionTests.cs` asserts exact 2024 disposal + Vorabpauschale figures against `data/test`. `TradersPlaceRegressionTests` asserts exact Trader's Place import + tax figures against `data/test/tradersplace/`. If tax logic changes, update expected values deliberately and explain why.
- Known limitation: ETCs are secured debt securities, not investment funds, so both gold ETCs carry `subject_to_vorabpauschale=false` and `tax_asset_class=other_security` (gains land on Anlage KAP Zeile 19, not KAP-INV). `IE00B4ND3602` (iShares Physical Gold) grants no delivery claim, so taxing its gain as an ordinary § 20 gain is correct — no longer a limitation. `DE000A0S9GB0` (Xetra-Gold) does grant a delivery claim and would be § 23 EStG tax-free after twelve months; that treatment **remains unmodelled** — deferred future work.
- Known thin spots: short-position tax semantics; Teilfreistellung variants other than 30%/0% (no such instruments in data yet); Vorabpauschale for a position held *beyond* the last ledger entry still needs an explicit as-of/through-year parameter (calculator currently replays only up to the last entry year). Multi-year Vorabpauschale accumulation and the §18(2) acquisition-month pro-ration are fully implemented and tested as of Phase 2. `TaxReportSummary.WithheldKESt` is summed only over sells (`AnnualTaxReportService.cs:65`) and `GermanTaxCalculator` sets it only on sell entries — no importer captures KESt withheld on a dividend. That no longer misroutes the form (routing is by source system, see above), but the KPI and Anlage KAP Zeile 37 still understate the withheld amount for a domestic account taxed mainly on dividends; documented as a gap rather than extending the importer.
- **No loss carry-forward / Verlustverrechnungstöpfe (estimate-only limitation).** Per §19 InvStG the previously-taxed Vorabpauschale is deducted at sale (`GermanTaxCalculator` line ~104, `rawProfit = proceeds − cost − usedVorab`), so a sale at a loss correctly grows the loss — covered by `GermanTaxCalculatorTests.Calculate_SellAtLossAfterVorabpauschale_DeductionEnlargesTheLoss`. But `AnnualTaxReportService` aggregates **strictly per year** and clamps each year's tax at `Math.Max(0, taxableBase) × 26.375%` — a net loss in year Y is **not** carried into other years, and there is **no separation of loss pots** (Aktien- vs. allgemeiner Verrechnungstopf; all sells/dividends/interest/Vorab share one base). Real losses are preserved by the Finanzamt as a Verlustvortrag, so WealthIQ's per-year `EstimatedTax` can **overstate** tax in years following a loss. Full Verlustverrechnungstöpfe + carry-forward (requires per-instrument bucket classification) is deferred future work.
- `AssetTransferEntry` / `PositionAdjustmentEntry` exist in the domain but tax replay fails fast with `NotSupportedException` if encountered — full transfer/adjustment semantics are unimplemented (no importer constructs them yet; YAGNI until IBKR data requires it).

## Coding conventions
- English for identifiers, docs, comments, commit messages.
- `PascalCase` types/methods/properties/enums; `camelCase` locals/parameters. Clear domain names (`Trade`, `Lot`, `Realization`, `Account`).
- One primary public type per file; file name matches the type; namespace mirrors folder path. Avoid huge files / deep nesting.
- Prefer implicit usings; remove unused; `System.*` before project usings; avoid ad-hoc global usings.
- `dotnet format`; 4 spaces, no tabs.
- `record` / `record struct` for immutable value-centric models; `readonly record struct` for tiny value objects.
- **`decimal` for money/quantities, never `double`.** Keep currency operations explicit and safe; use `DateOnly` vs `DateTimeOffset` intentionally.
- Treat nullable warnings as real; validate external input at boundaries (XML, UI); avoid `!` null-forgiving; prefer guard clauses.
- Throw specific exceptions for invariant violations with actionable messages; don't swallow exceptions; prefer structured results for recoverable business outcomes.
- `IReadOnlyList<T>` across boundaries; don't mutate caller collections; return updated values over mutating shared state.

## Testing conventions
- Add/update tests for every behavioral change. Names: `Method_Scenario_ExpectedResult`.
- Cover happy path, edge cases, invalid inputs. Keep tests deterministic — **no live network, no real-time, fixed reference data.**
- Prefer narrow, focused tests. Run targeted tests for touched areas; run the full suite before handoff.
