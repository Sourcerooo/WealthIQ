# FX Conversion Layer

This document describes the dedicated FX lookup and conversion layer used when source-currency ledger facts must be converted into EUR.

## Purpose

The canonical portfolio ledger stores imported facts in source currency.
Any conversion into EUR happens later through a dedicated FX layer so that:

- imported ledger entries stay immutable after import
- broker-provided FX values do not become implicit truth
- tax, valuation, dashboard, and reporting workflows can share one conversion mechanism
- base-currency handling can evolve later without rewriting ledger entries

## Core Rule

Ledger entries do not carry embedded conversion results.
They carry only source-currency facts.

## Current Contracts

- `IFxRateLookup`
  - returns an FX rate for `sourceCurrency -> targetCurrency`
  - supports date handling rules
- `FxRateLookupDateHandling`
  - `ExactDate`
  - `NextAvailableOnOrAfter`
- `FxConverter`
  - converts `Money` into the configured base currency using the lookup

## Current First Implementation

- Infrastructure adapter: `CsvFxRateLookup`
- Storage format: local CSV file
- Supported first target currency: `EUR`
- Current source currencies generated by helper script: `EUR`, `USD`, `GBP`, `CHF`

## CSV Format

The current CSV format is:

```text
date,currency,rate_to_eur
2024-01-02,USD,0.9132420000
2024-01-02,GBP,1.1543210000
2024-01-02,CHF,1.0723450000
2024-01-02,EUR,1.0000000000
```

Interpretation:

- `rate_to_eur` means `1 unit of source currency = x EUR`

## Date Handling Rules

- `Trade` conversion uses trade date with `ExactDate`
- `Dividend`, `Interest`, and `WithholdingTax` conversion uses booking date with `ExactDate`
- `Vorabpauschale`-related future date handling may use `NextAvailableOnOrAfter` when the legal date falls on a non-trading day

## Current Tax Replay Usage

The current tax pipeline uses the FX layer for:

- converting trade cost basis into EUR at the correct opening or closing date depending on long/short direction
- converting trade proceeds into EUR at the correct opening or closing date depending on long/short direction
- converting dividends, interest, and withholding tax into EUR at booking date
- converting open-lot acquisition costs into EUR for `Vorabpauschale` calculations

## Fail-Fast Rules

- missing FX rate for a required date is an error
- unsupported target currency in the current CSV provider is an error
- no silent fallback to broker FX values is allowed
- no implicit backfill is allowed unless the calling workflow explicitly selects `NextAvailableOnOrAfter`

## Scripted Data Generation

The repository contains `scripts/download_fx_rates.py` to download five years of daily FX data for `EUR`, `USD`, `GBP`, and `CHF` and write it to CSV.

The script is a data-preparation tool, not part of the runtime C# application.
